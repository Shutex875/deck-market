# Локальная база BastDecks

Локальный сервер использует SQLite `backend/data/bastdecks.db`. Скопируйте `.env.example` в `.env` при новой установке и запустите из папки `backend`:

```powershell
npm.cmd exec -- prisma migrate deploy
```

Относительный путь SQLite в `DATABASE_URL` считается от папки `backend/prisma`. Docker Compose использует свой постоянный том `backend_data` и задаёт собственный `DATABASE_URL`.

Чтобы дать пользователю право изменять общий мета-каталог, задайте `CATALOG_OWNER_ID` в `.env` равным его `User.id` из SQLite и перезапустите backend. Право привязано к ID и сохраняется при смене логина. Без этой настройки общий каталог доступен только для чтения.

## Резервное копирование

Для команд ниже нужен Node.js 22.13 или новее. Запускайте их из `backend`.

```powershell
npm.cmd run db:backup
```

Команда создаёт согласованный снимок в `data/backups` при стандартном пути к базе. Для копии на другом диске укажите путь к новому файлу после `--`. Снимок проверяется на целостность и может быть создан при работающем сервере. Храните копии приватно: в них есть данные аккаунтов и сессий.

## Восстановление

```powershell
npm.cmd run db:restore -- ./data/backups/<имя-копии>.db ./data/bastdecks.restored.db
```

Укажите фактическое имя файла. После проверки восстановленной базы остановите backend, задайте `DATABASE_URL=file:../data/bastdecks.restored.db` в `.env`, примените миграции и запустите приложение. Команды копирования и восстановления требуют новое имя файла и защищают существующие файлы от перезаписи.
